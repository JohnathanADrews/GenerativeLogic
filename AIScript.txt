Topic: Symbols and Operators

In GML, we are using a binary system with 0 and 1, and the operators that go along with it such as AND, OR, and XOR, but what about the other operators? If I have a system with n symbols, I should have n^(n^2) binary operators and n^n unary operators. For systems having more than two symbols, this quickly becomes unwieldly. Please consider a few like base 8 or base 10. However, even with only two symbols, we still have 4 unary operators and 16 binary operators. Generally, only a few are used, such as NOT, AND, OR, and XOR, depending on the application. NAND, NOR, and XNOR are also used in some cases. In GML, we will describe all 4 unary operators and all 16 binary operators for completeness.

Consider a truth table. Generally, the columns will have a Standard Order to them. For example, a truth table with two variable will have rows { 00, 01, 10, 11 }. This will be the ordering we will use. The order of the variables is important too. If the variables are a and b, is a first, or is b first? this is important. Then, we have the output: for AND, it is 0001, and for OR it is 0111. Together, the variable ordering and the function definition is the Function Signature (or just signature or sig). In our example, AND would have a sig of {{a,b}, 0111}. Does that make sense?

Topic: Expressions

Part One - Setup

In GML, an Expression is a tree of nodes that are either operators or operands. Every leaf node is a operand, and operands are only leaf nodes. All other nodes are operators. So, expressions have three aspects: operands, operators, and Form. The Form is essentially the placement of parentheses when the exprression is rendered to text. Form matters, since, among other reasons, not all operators are commutative, and other properties, such as the associative property, are difficult to work out at every glance. For this reason, order of operations is defined explicitly by the Form (i.e. parentheses placement) unless otherwise stated. Common shorthand is acceptable in a non-formal document for brevity.

One caveat to the operators, is that an operator is not necessarily a static binary or unary operator. It too could be a variable operator, or it could be an interface provider similar to the operand.

Topic: Functions

In GML, a Function is defined by the function signature as was discussed with the operators. However, a function signature can have any number of variables, and the output, given Standard Order, will have a size 2^(number of variables). For example, if the function h = {{a,b,c}, 01101110}.


Topic: Function Factoring

In GML, we often generate unwieldly expressions. Consider the Q aggregator if all the expressions were fully rendered - it would be a real mess. To solve this problem in a way that allows us to evaluate a simple expression, first, we capture the expression as a function by generating the truth table. Then, we factor the function, attempting to generate an expression from the function. To do this, we use a the following: F(S) = G(S1) tau H(S2), where S, S1, and S2 are sets of binary variables, and S1 and S2 are both subsets of S. tau is an operator we are trying to factor on. Since we have 16 binary operators, we can simply spin through them to figure out which operators enable us to factor. Depending on S1, S2, and tau, F may or may not be factorable. If F is factorable, we can use the selected tau to build the expression.

Part 2 - Logic Generation Technique

To factor an expression, we can use a Factor Map. A factor map enables us to visually describe a solution finding process. Of course, it can also be done in a non-visual way. We could use a Factor Map to factor an arbitrary function and tau combination, but we really only need the Factor Map to capture a simpler pattern that can be applied more easily. 

To exmplain this, we will start with the example F = {{a,b,c,d}, [0111 1110 0111 0010]} (I have spaced blocks for human eyes). If I created a truth table and wanted to factor this into G({a,b}) and H({c,d}), I could put placeholder values g|i| and h|j|. Please print the truth table for verification.


Now, suppose you have F({a,b,c,d}) and you want to factor this into G({a,b}) tau H({c,d}), where tau is some binary operator. How would you do this, and what does it even mean? Well, look at the following truth table.

Now, suppose you created a new table, a Factor Map. On the vertical, you have the g variable {a,b} possibilities, and on the horizontal you have the h variable {c,d} possibilities. In each table cell, you have in each corner, starting in the upper left and going clockwise, variables x1, x2, x3,and x4. x1 has the property of top and left, x2 is top and right, x3 is bottom and right, x4 is bottom and left.

For the x values, you have the following 
x1 => g|i| = 0 AND h|j| = 0
x2 => g|i| = 0 AND h|j| = 1
x3 => g|i| = 1 AND h|j| = 0
x4 => g|i| = 1 AND h|j| = 1

In the center, you have a value for F, which is the f|r| value in the truth table according to the row.

Next, we select tau. Let's go with XOR in this case. With this, we can compute the theoretical x values and pop them in the table.

Finally, we search for a solution. In the top-left cell, we find a 1 value. Then we we go across, looking for 1 values with the same top/bottom alignment. If we do not find one in a a cell going across, then there is no solution. If there is, then we keep going. Similarly, as we go down cells, we need a 1 with the same left/right alignment. As we develop the solution, we need to continue the process until each cell has exactly one x value accepted. If the process has zero, two, three, or four accepted x values, then it is not a valid solution. As you can imagine, for some operators, the number of possible solutions can quickly get out of hand. The notation for a selected x value is g|i|/h|j|/x|k|.

So, what do you think? Is  F = {{a,b,c,d}, [0111 1110 0111 0010]} factorable on XOR? How about F = {{a,b,c,d}, [0100 1011 1011 0100]}?


As you can see, factoring a function can be expensive. We would rather capture the pattern and then apply it without the Factor Map. To do this, we can use the G variables as a block. Imagine the truth table where the G values are all on the left; they do not change until all the H variable combinations are exhausted. We will call this set or rows a Factor Block. We can then discern a pattern for each operator on a Factor Block. For example, XOR's pattern is that each block must have the same outputs repeated in each block, or the opposite must be in the block. For example, 1101 1101 1011 1101 is factorable on XOR, but 1101 1001 1011 1101 is not factorable due to the secon block. BLOCK and PASS operators are obvious. Also, there is symmetry, and XNOR is the same as XNOR.

If no factors can be found, another technique is Bit Entanglement. This is a technique where you replace an operand with an expression involving two or more operands. For example, F1 = a XOR b can become F2 = a XOR (t1 AND t2), where b is entangled with t1 and t2. Then, you can apply the factor to F2 instead of F1, and then potentially undo the entanglement if necessary, but it's not always necessary. You can even entangle multple operands. For example F1 = a XOR b can become F2 = (t1 OR t3) XOR (t1 AND t2).
